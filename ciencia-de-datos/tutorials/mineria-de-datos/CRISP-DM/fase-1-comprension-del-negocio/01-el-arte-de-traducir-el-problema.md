# El Arte de "Traducir" el Problema

La primera fase de CRISP-DM es el puente definitivo entre el caos del mundo comercial y la estructura del mundo de los datos. Un punto crítico: **los problemas de negocio casi nunca vienen listos ni empaquetados para ser resueltos con minería de datos**.

Aquí es donde la ciencia de datos se vuelve un **oficio artesanal** y la creatividad del analista juega el rol principal. El verdadero éxito de un proyecto rara vez depende de usar el algoritmo más complejo; radica en la habilidad de saber **reformular un problema comercial difuso como uno o más problemas de ciencia de datos**.

## El valor de los fundamentos

Tener un conocimiento sólido de las bases —como las [9 tareas canónicas](../../04-las-9-tareas-canonicas.md)— es lo que te permite ver soluciones novedosas donde otros solo ven métricas cayendo. Esto te ayuda a estructurar o "diseñar" el problema original dividiéndolo en subproblemas más fáciles de atacar:

| Problema de negocio difuso | Subproblema de datos |
|---------------------------|---------------------|
| "Estamos perdiendo clientes" | Clasificación: ¿qué clientes van a cancelar? |
| "Nuestros ingresos bajan" | Regresión: ¿cuánto gastará cada cliente el próximo mes? |
| "No entendemos a nuestros clientes" | Clustering: ¿en qué segmentos se agrupan naturalmente? |
| "Queremos vender más" | Emparejamiento por similitud: ¿qué clientes se parecen a nuestros mejores compradores? |

## No es un paso atrás, es la naturaleza del proceso

El escenario de uso inicial casi siempre es una versión simplificada. A medida que el proyecto avance, será necesario regresar a esta fase y ajustar el diseño para que se adapte a la realidad del negocio. No es un paso atrás; es la naturaleza iterativa del proceso que vimos en el [diagrama de CRISP-DM](../../../intro-ciencia-datos/02-el-proceso-de-ciencia-de-datos.md).
